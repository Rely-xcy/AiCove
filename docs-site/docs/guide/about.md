# 关于与更新

「设置 → 关于」显示应用信息，也是检查更新的入口。

## 版本与检查更新

顶部卡片显示 App 图标、应用名和一句简介。下方分为「版本与更新」和「项目与许可」，「版本」行显示当前版本号，项目链接仍指向 AiCove 自己的仓库、许可证与协议。

**点版本行手动检查更新**：优先查询 AiCove 的 GitHub Releases；只有网络、HTTP 或响应解析失败时，才自动改用 AiCove 自有发布服务。GitHub 已确认没有新版本时不会再查询备用服务。

发现新版本后，弹窗按版本从新到旧列出当前版本之后的**完整更新记录**，可以上下滚动，不再只显示前 16 行。GitHub 检查最近 100 条发布记录：稳定版通道只接收正式版，其它通道也接收预发布；不高于当前版本的记录不会提示。备用服务按所选通道检查版本，返回已保存的中间版本日志；旧服务尚未提供历史时仍显示最新一版日志。

检测到与当前应用匹配的安装包才显示「下载并安装」；GitHub Releases 的正式版或 RC 包不会提供给不同包名的 Beta 版覆盖安装。安装前仍需通过包名、签名和版本校验。首次需要允许「安装未知应用」，授权后回到 App 再点一次即可，安装包不会重下。没有合适安装包时可用「浏览器下载」；备用服务返回下载直链时，浏览器入口会打开该直链。

下载时显示百分比与已下载大小，关闭弹窗不会中断下载，再点「版本」行即可回到进度界面。下载失败可点「重试」或「浏览器下载」。已经是最新版会提示「已经是最新版本」；两个检查来源都失败时，手动检查会显示错误信息。首次检查发现新版本时也会正常提示。

## 自动检查更新

默认开启。打开 App 进主页时在后台异步检测，**每天最多成功一次**（检测成功后的当天不再重复）。发现新版本会自动弹出更新窗；网络失败时静默处理、不打扰你，也不占用当天那一次——下次启动会再试。

GitHub 不可用时会尝试备用服务；两个来源都失败时，自动检查静默结束，不影响其它功能，也不会被记为当天检查成功。

关闭开关后不再自动检测，但手动点版本行仍然可以检查。

## 下载镜像源

更新包默认从 `cdn.gh-proxy.com` 这个 GitHub 加速节点下载（`github.com` 直连在国内经常很慢甚至超时）。在同一页点「下载镜像源」可以改：

- **gh-proxy CDN**：默认节点。
- **gh-proxy 优选节点**：同项目的另一个节点，网络环境不同时可能更快。
- **直连 GitHub**：不使用镜像，直接从 `github.com` 下载。
- 也可以自己填任意加速前缀（形如 `https://你的镜像/`），支持 `{url}` 占位符写法。

镜像不可用时 App 会自动改用直连重试一次，所以填错也不会把更新卡死，只是多花一点时间。填完记得点「保存」。

## 其它入口

- **GitHub 仓库**：用系统浏览器打开源码仓库。
- **开源许可证**：本项目使用 GPL-3.0，点击打开完整的 LICENSE 文件。
- **用户协议**：用系统浏览器打开[用户协议](/terms)，了解使用规则、AI 与操作风险、第三方费用及开源权利。
- **隐私政策**：用系统浏览器打开[隐私政策](/privacy)，了解数据保存、联网传输、日志与备份的处理方式。

## 首次启动确认

首次启动 App 时，协议确认弹窗覆盖在主界面上，其中包含「用户协议」和「隐私政策」两个蓝色链接。点击任一链接，会使用系统浏览器打开对应全文；阅读后返回 App 再决定是否同意。确认状态读取期间主界面保持显示；首次引导和自动检查更新在同意后启动。

- **不同意**：退出应用。
- **同意**：继续使用，并记住确认状态，之后启动不再重复提示。

如需再次阅读，可随时进入「设置 → 关于」，分别点击「用户协议」或「隐私政策」。
