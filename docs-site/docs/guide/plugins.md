# 插件

::: warning 预览功能
插件功能正在分阶段开发。目前支持从插件商店安装，也支持从本地 `.zip` 文件导入，插件可以提供**技能**、**子代理**、**工作区工具**、**设置页入口（HTML 页面）**、**AI 工具**、**MCP 服务器**，以及**运行 hooks**（只读观察、工具/HTTP 请求改写，或全部 ASK 代审核，含高危）。AI 工具与 hooks 的业务逻辑在容器内的插件子进程中运行，不会进入 App 主进程；设置页页面在 WebView 中运行，通过宿主接口读写文件。MCP 复用现有的 HTTP/stdio 链路。提供商第一版支持 OpenAI 兼容服务。
:::

插件是一个 `.zip` 包，可以一次性带来若干技能、子代理、工作区工具、设置页入口、AI 工具、MCP 服务器和 OpenAI 兼容提供商，以及在运行节点收到通知、在工具执行前后拦截或改写结果的运行 hooks，并由你统一启停和卸载。想自己做一个插件，见[开发插件](/advanced/plugin-development)。

入口在「设置 → 插件」。

## 插件商店

插件页底部可在「已安装」与「插件商店」之间切换，左右滑动也可换页。开启开发者侧载后，中间增加「开发中」页。点击商店条目进入详情，再点安装查看包预览，确认后才安装；顶栏返回键回到原列表位置。商店可聚合全部来源，也可只查看一个来源。安装时下载索引指定的直链包或对应 GitHub Release 资产，校验插件 ID 和版本；索引提供包摘要时还会校验 SHA-256。作者名称可使用中文，重托管包的展示仓库不要求逐字相同；这些展示字段不能证明来源可信。只有 AiCove 内置官方源、源码仓库归属和包内仓库信息相符时才标为官方，其余按非官方安装确认处理。清单或摘要不符时拒绝安装，并显示原因。

列表底部为悬浮页签留出滚动空间，末项可以完整滚动到清晰区域。商店列表会标记「已安装」或「可更新」，安装失败原因显示在对应插件的详情页中。

商店顶部始终显示「插件源：当前名称」，列表加载中、为空或加载失败时也能点击换源。内置三个来源：

- **AiCove**：自己的商店，仓库为 https://github.com/Rely-xcy/AiCove-Plugins-Store ，索引为 https://raw.githubusercontent.com/Rely-xcy/AiCove-Plugins-Store/main/index.json 。
- **上游**：https://raw.githubusercontent.com/jieapi/AiCode-Plugins-Store/main/index.json 。
- **Muse**：https://raw.githubusercontent.com/xzyy03/Muse-Plugins-Store/main/index.json 。

点击「插件源」后，可选「全部来源」聚合所有内置和自定义索引，也可选单一来源。选择会保存，重启后仍沿用。切换范围时先清空旧范围的条目与错误，再加载所选范围；同一插件在不同来源中的条目保留各自的来源标记。

要添加自己的索引，在同一对话框的「自定义索引」中按行输入 **GitHub 仓库地址或索引 raw 直链**，一行一个，点击「保存」，然后点击上方新增的来源即可切换。GitHub 仓库地址默认读取 `main/index.json`；其他分支或路径请填索引文件链接。空行与重复地址会被忽略，非法地址会显示保存失败提示，原有配置不会被悄悄替换。删去对应行再保存即可移除自定义源；移除正在使用的源后会回到「全部来源」。三个内置源不能删除。

同源离线加载仍可回退到该源上一次的缓存；下拉刷新失败会保留已显示的同源条目。索引中单条记录无效或格式不兼容时会跳过，并显示跳过条数，其余有效插件仍可浏览；整个索引无法读取时显示错误，可重试或切换来源。要求更高 App 版本的有效条目仍会显示，但不能安装。

「可更新」只比较当前源中与已安装记录来源一致的插件，不会自动跨源升级；安装与替换仍需你确认。插件源码仓库不属于 AiCove 官方账号时，会显示「非官方」徽标。本地 zip 导入不经过索引。

插件设置里可以填**镜像加速地址**。加速按候选顺序依次尝试，前一个连不上或超时自动换下一个：

1. 你自己填的地址（可留空）
2. 内置候选：`ghfast.top`、`gh-proxy.com`、`ghproxy.net`
3. 直连 GitHub

所以即使某个公共镜像挂了也不影响使用。只影响 GitHub 托管的内容，其他主机的索引仓库保持原地址。

## 导入插件

1. 点右上角「＋」，在文件选择器里选中插件的 `.zip` 文件。
2. 读取完成后弹出「安装插件」，依次显示：名称、版本、发布者、简介，以及**将提供的内容**（每个技能、子代理的名字和说明）。
3. 确认安装后，插件声明的贡献随启用生效；安装弹层不再逐项询问权限。
4. 点「安装」。新插件装好后默认启用并出现在列表里；替换已安装插件时沿用原来的启用状态（AI 的技能清单需要新开会话才会刷新，见下文）。

如果文件有问题，会弹窗逐条列出原因，什么都不会被安装；常见原因见本页末尾的〈出错怎么办〉。

## 组合包与发布

导入的 ZIP 若包含多个一级插件目录，会按组合包逐个校验和安装；单项失败不会假报为整包成功，结果弹层列出成功与失败数量。替换仍沿用原启停状态，并执行同一套安装后处理。

右上角「发布」入口可读取插件清单、核对包信息并导出包。远端提交接 AiCove 自有服务；当前构建未配置发布后端时会明确提示不可提交，不会使用 Muse 的上传令牌，也不会把导出包当作已发布。

## 安装前先看这几点

- **AiCove 无法核验本地文件的来源。** 请只安装你信任的人提供的插件，弹窗里显示的「源码仓库」是插件自己写的，AiCove 不会去核实。
- **技能和子代理的内容会直接影响 AI 的行为。** 它们是一段段指令，名称和描述还会写进 AI 的系统提示词。装一个你没读过的插件，就等于让 AI 照着别人写的指令办事。
- **带运行时的插件会在容器里启动进程。** AI 工具与 hook 的逻辑在本地容器的子进程里运行，可以读写自己目录下的文件、安装 npm/pip 依赖、访问网络，与 Bash 同级。容器未初始化或缺少 node/python 时这类插件不可用；声明 `resident: true` 的插件会在 App 启动或首次调用后常驻，持续占用内存与容器资源。只安装你信任的插件。
- **工作区工具会把页面里的命令发到终端。** 这些命令在你点击运行后执行，安装前请确认你信任插件作者。
- **Shizuku 权限需要在插件详情中单独开启。** 插件声明用途后才会出现开关；开启后该插件可直接执行任意 Shizuku 命令。
- **插件页面可以读写文件和执行命令。** 文件接口使用当前执行环境的路径，`data://` 指向插件自己的数据目录；文件系统根、home 和配置根不允许整体删除或重命名。具体文件接口不等于独立沙箱，插件进程及其命令也能访问容器内的文件。只安装你信任来源的插件。
- **运行 hooks 分只读、可写与代审核三种。** 只读 hook 只拿到运行标识、模式、状态、工具调用次数这类元数据，看不到消息正文、工具参数或结果；可写 hook 会在工具执行前拿到参数、在成功结束后拿到结果，能拒绝调用、改写参数或改写成功结果的数据，但不能替你批准工具，也不能绕过权限与 PLAN 模式。HTTP 请求 hook 还能看到并改写 URL、headers 与 body，其中已识别的敏感请求头以占位符显示；跨站点改写会剥离原敏感头。请求正文仍可能包含对话内容。代审核 hook 能批准原本需要你确认的工具调用，包括 Shizuku、提权、配置修改、删除子代理与危险 rm；但不能覆盖宿主拒绝、PLAN 模式，也不能代审自己的工具。只安装你信任的插件。
- **MCP 插件会联网或启动进程。** HTTP 服务器会访问网络，stdio 服务器会在当前工作区的容器或 SSH 后端启动命令；只安装你信任的插件。
- 子代理的行为仍受当前模式约束（Plan 模式下只读），插件无法提升权限，也不能指定使用你的哪个供应商或模型——插件子代理一律沿用主会话的模型。

## 列表与详情

插件显示名可直接使用中文或多语言文本。列表、详情标题、安装预览及宿主生成的插件提示按 App 当前语言显示；Android 返回 `zh-Hans-CN` 等中文标签时也会匹配对应中文名称。插件未提供对应译名时使用其默认文案，宿主不会自动翻译。插件 ID 是独立的稳定标识，不因中文显示名改变；插件网页、通知正文等插件自己提供的文本仍由插件负责本地化。

插件列表加载时会显示等待提示。每行展示图标、名称、版本和作者等信息，右侧开关可直接启停；有更新时显示版本变化与「可更新」标记，仍支持左滑卸载。下拉可刷新安装列表和更新信息。安装、启停和卸载完成后会显示结果；处理中的插件会显示进度并暂时禁用重复操作。卸载失败时详情页会保留，方便重试；若安装记录已移除但文件清理失败，会单独提示残留清理问题。

| 状态 | 含义 |
| --- | --- |
| 已启用 | 插件运行正常，已授权的内容生效 |
| 已停用 | 你关掉了开关，它提供的内容全部不生效 |
| 已损坏 | 插件文件丢失或被改动过，无法启用；请卸载后重新导入 |
| 不可用 | 这个插件与当前版本的 AiCove 不兼容 |

点击列表项进入详情页，顶栏显示当前插件名，右上角提供卸载并要求确认；界面重建后会保留已打开的详情。详情先展示插件头卡，再依次展示启停、权限与依赖等常用操作，以及版本信息和提供的内容。若插件声明了自身专属配置页面（`configPage`），顶部通过分段控件分为两个视图：

- **插件管理（系统固定配置）**：
  - **启用插件**：总开关；
  - **专属配置快捷入口**：点击直接前往插件自己的配置界面；
  - **简介** 与 **信息**：版本、发布者、许可证、插件自述的源码仓库、来源（本地导入）；
  - **提供的内容**：这个插件带来的技能、子代理、工作区工具、设置页入口、AI 工具、Hook、MCP 服务器和提供商；可写 Hook 会标注为「可写 Hook」。插件停用时显示为半透明；
  - **启用插件**：总开关；关闭后所有贡献和插件页面都不再生效；
  - **卸载插件**：删除插件文件和它的授权记录，它提供的技能、子代理和工具一并消失，无法恢复。
- **插件配置（WebView 专属配置页面）**：
  - 展示插件包内自带的配置界面（用于填写 API Key、设置参数或个性化选项）；
  - 自动适配当前 App 的主题配色（背景、表面、字体、间距与圆角）、暗黑/浅色模式，与整个应用保持一致的视觉质感。

若插件未声明专属配置页面，则整屏直接展示系统固定配置，保持极简直观。

## 在对话里怎么用

- **技能**：和普通技能一样，AI 会按需加载，你也可以在输入框用 `/` 菜单触发。插件技能的名字带着插件 ID 作前缀，形如 `community.demo-kit:project-notes`，所以不会和你自己建的技能重名。
- **子代理**：同样带前缀，AI 派发时用这个完整名字；也会出现在 AI 可派发的子代理清单里。
- **AI 工具**：出现在 AI 的工具清单里，名字形如 `plugin__community_demo-kit__echo`。首次调用会弹工具授权，确认后由容器内的插件进程执行并返回结果。
- **工作区工具**：在右侧项目工具抽屉的「全部工具」里添加，打开详情后由插件页面执行命令并展示输出。短命令走 `aicode.bash`；后台任务可用 `aicode.terminal` 创建共享标签，默认隐藏，需在「设置 → 终端设置 → 显示插件运行」开启后才在终端页可见。
- **设置页入口**：插件可以在设置页注册自己的页面。装好后入口出现在对应分组的末尾，副标题标明插件来源；点开是插件自带的 HTML 页面，颜色跟随 App 的深浅色与主题。停用或卸载插件后入口消失。
- **MCP 服务器**：插件启用后会自动连接，工具以 `mcp__plugin__…` 的形式出现在 AI 工具清单里；停用或卸载插件会断开连接并移除工具。
- **插件提供商**：启用后出现在设置 → 提供商和模型选择中，带「插件」标记。插件负责运行 OpenAI 兼容服务；宿主把地址注册成普通提供商条目，你可以像自建渠道一样改名、改地址、改凭据、启停，也可以从插件服务拉取并选择模型。停用或卸载插件后，该插件注册的条目会被删除。服务未就绪时请求失败，不会自动切到其他付费渠道。
- **插件提示**：插件可以在对话里显示可关闭的提示条，最多同时排队 3 条；带按钮的提示点击后会回调插件自己的逻辑。
- **运行 hooks**：只读 hook 在 App 启动、运行开始/结束、模型请求开始/结束、工具开始/结束与上下文压缩时收到通知，用来记录日志或统计，不影响这一轮的请求与结果；可写 hook 在工具执行前拦截（可拒绝或改写参数，改写后重新走工具授权），在工具成功结束后改写结果数据，或在每次 provider HTTP 请求前改写 URL、headers、body。HTTP hook 看到的敏感鉴权头为占位符；跨站点改写不继承原敏感头。所有可写 hook 失败、超时或格式不合法时保持原值继续，不会自动放行。

右侧项目工具抽屉可以从屏幕右半部分向左拖动拉开：拖动时跟随手指，松手后按拖动距离和速度吸附到打开或关闭；点遮罩或向右拖动可关闭。

`/` 菜单每次打开都会重新读取，新装、停用或卸载插件后马上可见。不过和普通技能一样，**AI 的可用技能清单在会话开始时生成，需要新开会话才会看到更新**；子代理清单则在下一轮对话就会刷新。

「设置 → 技能」和「设置 → 子代理」两个页面只列出你自己创建的内容，插件提供的内容请到「设置 → 插件」里查看。

## 总结并切换会话

安装「总结并切换会话」插件后，从聊天侧栏底部打开入口。选择要总结的会话及其所在工作区，再选择新会话放在哪个工作区；点击「总结并新建会话」，插件读取记录并等待模型生成要点，完成后切换到新会话并关闭插件页。失败或超时时保留页面并显示原因，不会假报成功。

插件文件独立于 APK 保存：升级 App 不会更新已导入的插件。旧版入口打开后空白时，请导入修正版 `1.0.1` 的 ZIP，确认替换同名插件；原聊天记录不会被删除。

## 更新与替换

开发者调试时可在「设置 → 插件」右上角的设置按钮中打开「开发者侧载」，把插件目录放到容器的 `~/.aicove/plugin-dev/<项目>/`（每个目录需含 `plugin.json`），到「开发中」页下拉刷新并点项目进入详情，选择「安装」或「重载」；开启期间保存文件会自动重载。该模式不参与在线更新，普通 `.zip` 导入仍然可用。打包会跳过 `node_modules`、`.git` 等目录，依赖请通过 `runtime.dependencies` 准备或预先 bundle。

再次导入一个**同 ID** 的插件包，就是替换安装：弹窗里会提示「已安装 x.y.z 版」，继续会整体替换旧版本；如果导入的就是已安装的同一个文件（内容逐字节一致），弹窗会告诉你；同一个插件被重新打包过，即使内容没变，也会被当作不同的包。

替换后保留原来的启用或停用状态；即使版本号和 ZIP 完全相同，重新安装也会让插件运行时重新加载。安装过程中 App 意外退出时，下次启动会根据安装记录恢复完整版本；恢复失败时保留待恢复目录，并在日志中记录原因。

准备依赖的结果会保存，重启后仍然有效。重新安装后，旧安装的准备中提示和失败信息不会沿用。如果准备期间插件被替换或状态写入失败，页面会提示重新准备依赖，不会把旧安装的结果标到新插件上。

安装记录已更新为新格式，升级后不建议退回旧版 App；旧版不能识别新的安装记录。

## 和其他功能的关系

- **远程 SSH 模式**：插件和它的授权保存在手机上，切换到 SSH 模式不受影响，也不会被上传到服务器。
- **备份与还原**：插件安装包仍需另行安装。插件声明备份能力并由你在详情里单独授权后，备份页可勾选它的附加数据。插件只处理自己的暂存区段，不会收到整个备份包；导入时也只向仍已安装、启用且获授权的插件交回对应数据。恢复摘要会列出成功、跳过与失败数量。
- **工具授权**：插件的授权只决定「它的内容生不生效」，不会改变你在「工具授权」里对 AI 工具的任何设置。

## 出错怎么办

| 提示 | 怎么办 |
| --- | --- |
| 这个文件不是有效的 ZIP 压缩包 | 确认选的是 `.zip`，并且没有下载一半；有些文件管理器会把 `.zip` 显示成其他类型，换一个文件管理器再试 |
| 压缩包根目录里没有 plugin.json | 打包时多套了一层目录，需要让 `plugin.json` 直接位于压缩包根部 |
| 此版本暂不支持的内容类型 / 字段 | 这个插件用了当前版本还没实现的功能（如提供商、新的 hook 事件）。等 AiCove 升级，或联系插件作者提供兼容版本 |
| 插件要求的插件接口版本不兼容 | 插件针对更新（或更旧）的 AiCove 编写，需要升级 AiCove 或更换插件版本 |
| 压缩包过大 / 文件过多 / 路径不安全 / 重复文件 | 包不符合安全限制，请联系插件作者；AiCove 不会放宽这些限制 |
| 其余「plugin.json 缺少/无效字段」「内容无效」「文件不存在」 | 都是插件包本身的问题，提示里会写明具体字段或文件，转给插件作者修复 |
